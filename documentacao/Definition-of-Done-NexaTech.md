# Definition of Done (DoD) - NexaTech

Este documento estabelece os critérios obrigatórios para que uma funcionalidade seja considerada concluída e pronta para entrega.

---
| Critério | Descrição |
|----------|-----------|
| 1. Código desenvolvido | O código necessário para atender a US foi escrito e está disponível no repositório. |
| 2. Código revisado | O código passou por Code Review de pelo menos um membro do time. |
| 3. Testes realizados e aprovados | A US foi testada (unitário, integração ou manual) e todos os testes passam. Evidência: task em "Em Teste" ou data de entrega. |
| 4. Critérios de aceitação cumpridos | Todos os critérios de aceitação definidos na DoR foram verificados e atendidos. |
| 5. Documentação atualizada | A documentação necessária (README, API, comentários) foi atualizada se a US impactou o sistema. |
| 6. Aceitação pelo Product Owner (PO) | O PO (ou Scrum Master) confirmou que a US está concluída. Evidência: data de entrega preenchida ou comentário. |
| 7. Sem bugs críticos | Não há bugs ou erros que impeçam a funcionalidade principal da US. |
| 8. Concluído dentro da Sprint | A US foi finalizada dentro da Sprint planejada. |
